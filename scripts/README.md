# scripts/ 目录说明

## 🛠️ 概述

`scripts/` 目录包含项目自动化脚本，用于简化开发、构建、测试和发布流程。

## 📁 脚本文件

### 📦 publish.sh - 发布脚本

**作用**: 自动化发布流程脚本

- **功能**:
  - 版本号更新
  - 依赖安装
  - 代码构建
  - 包发布
  - 标签创建
- **使用方法**:

  ```bash
  # 发布补丁版本 (1.0.0 -> 1.0.1)
  ./scripts/publish.sh patch

  # 发布小版本 (1.0.0 -> 1.1.0)
  ./scripts/publish.sh minor

  # 发布大版本 (1.0.0 -> 2.0.0)
  ./scripts/publish.sh major
  ```

## 🔧 脚本开发规范

### 命名规范

- 使用 kebab-case 命名脚本文件
- 脚本名应该清晰表达其功能
- 可执行脚本使用 `.sh` 扩展名

### 脚本结构

```bash
#!/bin/bash
# 脚本说明
# 作者: 作者名
# 日期: 创建日期

set -e  # 遇到错误立即退出

# 脚本逻辑
```

### 错误处理

- 使用 `set -e` 确保遇到错误时脚本停止
- 添加适当的错误提示信息
- 记录操作日志

## 📋 常用脚本示例

### 构建脚本

```bash
#!/bin/bash
echo "开始构建项目..."
pnpm run build
echo "构建完成！"
```

### 测试脚本

```bash
#!/bin/bash
echo "开始运行测试..."
pnpm run test
echo "测试完成！"
```

### 清理脚本

```bash
#!/bin/bash
echo "清理构建文件..."
rm -rf dist/
rm -rf packages/*/dist/
echo "清理完成！"
```

## 🚀 添加新脚本

1. **创建脚本文件**: 在 `scripts/` 目录下创建新文件
2. **添加执行权限**: `chmod +x scripts/script-name.sh`
3. **更新文档**: 在 README 中添加脚本说明
4. **测试脚本**: 确保脚本可以正常运行

## 📚 脚本维护

- 定期检查脚本是否正常工作
- 更新脚本以适应项目变化
- 添加适当的注释和文档
- 测试脚本在不同环境下的运行情况

## ⚠️ 注意事项

- 脚本应该具有幂等性（多次运行结果一致）
- 添加适当的错误处理和日志记录
- 确保脚本在 CI/CD 环境中可以正常运行
- 避免在脚本中硬编码路径，使用相对路径或环境变量
